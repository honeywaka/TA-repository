# TA-Repository 资产命名规范

> 版本：v1.0  
> 适用范围：UE5 项目所有 Content 目录资产  
> 目的：看一眼文件名就知道这是什么东西、归谁管、干嘛用的

---

## 1. 核心前缀速查表（必遵守）

| 前缀 | 全称 | 中文 | 示例 | 备注 |
|---|---|---|---|---|
| `SM_` | Static Mesh | 静态网格 | `SM_Wall_01` | 场景物件、建筑构件 |
| `SK_` | Skeletal Mesh | 骨骼网格 | `SK_Hero_Body` | 带骨骼的角色/动物/载具 |
| `M_` | Material | 材质 | `M_Ground_Grass` | 母材质，原则上不带参数实例化 |
| `MI_` | Material Instance | 材质实例 | `MI_Wall_Brick_Red` | 基于母材质调参后的实例 |
| `T_` | Texture | 贴图/纹理 | `T_Wall_Brick_BC` | 需加通道后缀（见下） |
| `PS_` | Particle System | 粒子系统 | `PS_Fire_Camp` | Niagara 系统也沿用此前缀 |

---

## 2. 贴图通道后缀（贴在 T_ 后面）

| 后缀 | 含义 | 示例 |
|---|---|---|
| `_BC` | Base Color / Albedo | `T_Rock_Granite_BC` |
| `_N` | Normal | `T_Rock_Granite_N` |
| `_ORM` | Occlusion + Roughness + Metallic（打包） | `T_Rock_Granite_ORM` |
| `_R` | Roughness | `T_Water_R` |
| `_M` | Metallic | `T_Gold_M` |
| `_AO` | Ambient Occlusion | `T_Prop_AO` |
| `_E` | Emissive | `T_Lamp_E` |
| `_A` | Alpha / Opacity | `T_Fence_A` |
| `_H` | Height / Displacement | `T_Terrain_H` |

## 4. 命名格式公式

```
前缀_功能描述_序号/变体
```

**示例**：
- ✅ `SM_Rock_Desert_01`
- ✅ `MI_Wall_Concrete_Broken`
- ✅ `T_Ground_Mud_BC`
- ✅ `BP_Trap_Spike_02`
- ❌ `rock01`（无前缀、全小写）
- ❌ `New Blueprint`（带空格、无意义名）
- ❌ `Material`（太泛、无法区分）

---

## 5. 文件夹层级建议（Content/ 下）

```
Content/
├── Blueprints/        # BP_*.uasset
├── Materials/         # M_*.uasset、MI_*.uasset、MF_*.uasset、PP_*.uasset
├── Meshes/            # SM_*.uasset、SK_*.uasset、SKA_*.uasset
├── Textures/          # T_*.uasset、RT_*.uasset
├── Effects/           # PS_*.uasset
├── Animations/        # A_*.uasset
├── UI/                # W_*.uasset
├── Data/              # DA_*.uasset、E_*.uasset、ST_*.uasset
└── Core/              # GM_*.uasset、GI_*.uasset、PC_*.uasset、P_*.uasset、I_*.uasset
```

---

## 6. 为什么要这么做？

1. **搜索快**：UE Content Browser 里搜 `SM_` 瞬间列出全部静态网格
2. **协作不打架**：两个人不会同时建一个叫 `Rock` 的东西
3. **代码/蓝图引用稳**：`LoadObject<UTexture2D>(nullptr, TEXT("T_Rock_BC"))` 语义明确
4. **校招面试加分**：简历写"参与项目并制定资产命名规范"——比"会 UE" 听起来专业十倍
